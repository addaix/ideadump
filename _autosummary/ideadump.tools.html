ideadump.tools#

The verbs: plain functions, JSON-able arguments in, JSON-able dicts out.

This module is the single source of truth for what ideadump does; the command line (ideadump.__main__) and the shipped agent skill are views of the list TOOLS. Every verb takes a files store (see ideadump.store), so

>>> files = {}
>>> r = add("Maybe a tool to dump ideas into, with a bit of research", title="Idea dump",
...         tags="tools, notes", files=files, now="2026-11-14T10:00:00+01:00")
>>> r["id"]
'2026-11-14-idea-dump'
>>> sorted(files)
['README.md', 'ideas/2026-11-14-idea-dump/README.md', 'ideas/2026-11-14-idea-dump/idea.json']
>>> find("research tool for ideas", files=files)["hits"][0]["id"]
'2026-11-14-idea-dump'

Verbs never print and never exit; each result carries a text field, the human rendering, which the command line prints.

ideadump.tools.add(words, *, title=None, summary=None, tags=None, source=None, status='new', files=None, data_dir=None, now=None)[source]#

Capture an idea: the owner’s words verbatim, plus an optional title, summary and tags.

words is kept exactly as given (dictation slips included); put the cleaned-up reading in summary. tags is comma-separated. source says where it was captured (a session name, “phone”). Returns the new id.

Return type:

dict

ideadump.tools.find(query=None, *, file=None, limit=10, files=None, data_dir=None, score=None)[source]#

Ideas related to a query, best first: a few words, or a page of text in file.

For “is anything I’ve been working on related to my ideas?”, put a description of recent work (ledgers, issue titles, commit subjects) in a file and pass --file. Each hit lists the words it shares with the query, so a weak match is visible.

Return type:

dict

Attach a research note (Markdown) to an idea, from text or a file path.

depth is light (the quick pass at capture) or deep (a full report). Notes are never overwritten: a second note the same day gets its own file.
